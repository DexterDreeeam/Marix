Intent stage runtime migration

生成时间：2026-08-05 15:26 UTC+08:00

用七种代码级 StageType 和各 Stage 独立的 Result JSON 替代 workflow tools；IntentRuntime 负责六种 Intent stage，InvocationRuntime 独立负责 continuation，StageAssembler 集中装配所有模型 prompt。

目标

  1. 建立代码级 stage 状态机
    1. Intent：Planning、ToolCalling、Replan、Infeasible、SubIntentComplete、Complete。
    2. Invocation：Continue；不再伪装为 tool invocation。
  2. 移除模型可见及隐藏的 workflow tool 类型；模型只看到 ordinary tools。
  3. 每个 stage 使用独立 template 和独立 Result schema；template 内容不暴露 Rust stage 类型名，只有 ToolCalling 返回 native tool call。
  4. 保持相同 ordinary tool schema 前缀；非 ToolCalling stage 使用 tool_choice none，ToolCalling 使用 required。

I04server/prompt/prompt.rsStage template 可以引用 module；module 文件只能包含 text/parameter，禁止再次引用任何 module。解析阶段建立全局参数所有权，名字冲突立即 panic。
pub(crate) enum PromptMarker {
    Parameter { name: String, repeatable: bool },
    Module { name: String, repeatable: bool },
}

// 支持的 marker：
// {{#name}}   {{^#name}}
// {{@module}} {{^@module}}

// 约束：
// - module 从 prompt/module/<name>.prompt 加载；
// - 只有 prompt/template 下的 template 可以包含
//   {{@...}}/{{^@...}}；
// - module 内出现任何 module marker 立即 panic；
// - template 外部参数、不同 module 参数之间 name 冲突
//   立即 panic；
// - repeatable module 内参数必须使用 {{^#name}}；
// - 同组 required 参数必须覆盖相同 tag 集合；
// - repeatable parameter 不在 repeatable module 内时，
//   pack_tag=name；
// - required 参数在 assemble 时没有 injection 立即 panic。

// assemble 规则：
// 1. unknown parameter、non-repeatable 二次 inject、
//    non-repeatable 携带 tag：立即 panic。
// 2. required 参数零 injection：assemble 立即 panic。
// 3. 单个 package 可以全部 tag=None；只渲染一次 module。
// 4. 一旦同 pack_tag 存在多个 package，所有 injection
//    必须有 tag；缺 tag、同参数重复 tag、组内 required
//    参数缺失：立即 panic。
// 5. {{^@module}} 按 tag 的字符串升序稳定渲染 module；
//    同一 tag 下参数按 module marker 顺序注入。

目的

C02 · 现有 prompt/template/ 与 prompt/module/

精确位置
prompt/template/ 新增七个 Stage template；prompt/module/ 新增 PlanItem、SubintentResult、ToolCall、FailedPlan、PreviousSummary 五个 module。
改动内容
沿用现有 Prompt 的 template/module 两层结构，不新建 stage 子目录。每个 Intent 判断 template 只询问一个问题；肯定分支返回语义结果，否定分支统一返回 reject + reason。Template 使用 {{^@plan_item}} 等 module marker；module 内使用 {{^#plan_goal}} 等 parameter marker。
目的
模型只完成当前 Stage 的判断；重复 context 的分组和顺序由现有 template/module 系统表达。
接口最终定义
Planning/Replan：plan|reject；Infeasible：infeasible|reject；两种 Complete：intent_complete|reject；ToolCalling 对应 native calls；InvocationContinue 对应 invocation_continue|invocation_complete。
内部实现位置
  1. StageType 只映射 template 文件名，StageAssembler 使用现有 Prompt::load。
  2. module 内禁止再次出现 module marker；repeatable module 内全部字段使用 {{^#name}}。
  3. runtime 给同一记录的字段注入完全相同的 String tag；module instance 按 tag 字符串升序稳定展开。
  4. InvocationContinue.prompt 分别产出有 cursor/无 cursor的结果。
